Architecture Overview

The system is a layered client–server web application (see DD-1). The browser UI (C1) talks only to the API Gateway (C2). Behind the gateway, application services handle accounts (C3), characters and parties (C4), progression and rewards (C5), and stats (C6). Both calculation components read game rules through the Game Data Adapter (C7), so no component contains game-specific code. All data lives in one database (C8), and a background service (C9) checks data integrity and manages backups.

Component Summary

IDComponentResponsibility
C1Web UI (Presentation Layer)Semantic, responsive browser interface for accounts, games, characters, parties, and the consolidated progression view.
C2API Gateway & AuthenticationSingle entry point: terminates TLS, validates sessions, and exposes one aggregated endpoint per view.
C3Account ManagerSign-up, sign-in/out, account ownership checks, and permanent account deletion.
C4Character & Party ManagerCreates, edits, and deletes characters and parties; validates manual level/EXP entry.
C5Progression & Rewards EngineStateless: computes EXP, materials, rewards, and equipment/location unlocks for next-level and target-level views.
C6Stat CalculatorStateless: computes before-and-after stats and per-stat differences from base values, item stats, and multipliers.
C7Game Data AdapterReads each game definition and exposes every progression model through one common track interface.
C8Database (User Data + Game Definitions)Relational tables for user data with ACID transactions; versioned JSON documents for game definitions.
C9Data Integrity & Backup ServiceScheduled reference checks on game data, backups with point-in-time restore, and backup retention.
