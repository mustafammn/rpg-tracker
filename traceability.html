Coverage Notes

  • Full coverage. Every functional and non-functional requirement maps to at least one component, and every component maps to at least one requirement.
  • The consolidated view (FR-4) is shared work. No single component produces it. C5 computes EXP, materials, rewards, and unlocks (FR-4.1 to 4.3, 4.5, 4.6). C6 computes stat deltas (FR-4.4). Both read game rules through C7, and C1 renders the combined result in one view. FR-7 is the same calculation run over a range of levels.
  • Extensibility is concentrated in C7 and C8. FR-8, NF-6, and NF-7 are met because game rules are stored as data (C8) and normalized by the Game Data Adapter (C7). The calculation components never contain game-specific code.
  • Security is enforced at one boundary. NF-5.2 is enforced first by C2, which authenticates every request. C3 and C4 then confirm that the user owns each account, character, and party record before reading or changing it.
  • Accessibility belongs to C1 alone. NF-4.1 to NF-4.4 are presentation concerns. Because C1 receives plain structured data from the API, every chart can also be rendered as a data table for screen readers.

See the Design Rationale for why the components are divided this way. Each design decision there names the requirements that drive it.
